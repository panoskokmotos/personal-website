## 🔥 P0 — Ship this week (bugs breaking user flows)

### 1. `closeSearch` is undefined — "Try AI chat" button throws ReferenceError

- **What**: The no-results state in site search renders an inline `onclick` that calls `closeSearch()`, which is never exposed globally; only `window.__ssClose` exists.
- **Where**: `search.js:63`
- **Why it matters**: Every visitor who searches and gets no results and clicks "try the AI chat instead" gets a silent JS error — the chat never opens. This is the most important fallback CTA in the search flow.
- **Effort**: S
- **Suggested fix**:
  - Change `onclick="openSearch(); closeSearch(); setTimeout(openChat,120)"` → `onclick="window.__ssClose(); setTimeout(window.openChat,120)"`.
  - Remove the spurious `openSearch()` call (search is already open at that point).

### 2. AI chat response injected via unescaped `innerHTML` — XSS vector

- **What**: The bot reply from the Cloudflare Worker is rendered via `p.innerHTML = parseMarkdown(text)` where `parseMarkdown` (`renderMarkdown` in `shared.js`) applies regex transforms on raw text *before* escaping HTML entities. A prompt-injected response containing `<img src=x onerror=alert(1)>` executes in visitors' browsers.
- **Where**: `chat.js:71`, `shared.js:29-42`
- **Why it matters**: If a visitor manipulates the AI into returning raw HTML (prompt injection is a known attack), arbitrary script can run in their browser, or a compromised worker can target all site visitors.
- **Effort**: S
- **Suggested fix**:
  - In `renderMarkdown` (shared.js), HTML-escape the raw `text` before applying markdown patterns: replace `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;` first.
  - The regex patterns for `**bold**`, `*italic*` and URL detection operate on plain text, so escaping first is safe and correct.

### 3. Duplicate drag handlers on logo marquee — animation fights itself

- **What**: Two entirely separate drag-scroll implementations both attach `mousedown`/`touchstart` to the same `.logos-strip-wrap` element: one using `scrollLeft` (lines 123–153) and one using CSS `transform` (lines 869–928). Both fire simultaneously on every drag.
- **Where**: `script.js:123-153` (scroll-based) and `script.js:869-928` (transform-based)
- **Why it matters**: Dragging the logo strip produces erratic behaviour — the first handler fights the second. On touch devices, the two `touchstart` handlers can also prevent `passive: true` from applying consistently.
- **Effort**: S
- **Suggested fix**:
  - Delete the first implementation (lines 123–153 — the `scrollLeft` version). It was clearly superseded by the second, more complete implementation that uses CSS `transform` for seamless animation resume.
  - The second handler at line 869 already handles both mouse and touch correctly.

## ⚡ P1 — High ROI (UX friction blocking conversion)

### 4. "Now" page shows "Updated March 2026" — 7 months stale

- **What**: `now.html` renders "Last updated March 2026 · San Francisco & Athens" in the page body and repeats "Updated March 2026" in OG/Twitter meta descriptions. `dateModified` in schema says `2026-07-04` but the visible text is still March.
- **Where**: `now.html:42`, `now.html:50`, `now.html:77`, `now.html:221`
- **Why it matters**: The "Now" page is the highest-trust signal that Panos is actively building. A 7-month-old timestamp signals abandonment to anyone who notices. Investors and collaborators who arrive via search often land here.
- **Effort**: S
- **Suggested fix**:
  - Update the visible body text date and all four meta occurrences to the actual last-update date.
  - Consider displaying the date dynamically from the schema `dateModified` field to prevent this drift in future.

### 5. `notifySecret` hardcoded in public JS — enables notification spam

- **What**: `shared.js:21` ships `notifySecret: 'panos-notify-2026-xyz'` in plain sight. Anyone who views source can POST arbitrary events to `/notify`, triggering emails to Panos's inbox from any origin.
- **Where**: `shared.js:21`, `cloudflare-worker.js:187-229`
- **Why it matters**: Even with the worker's rate limiter (20 req/hour per IP), a distributed attack from multiple IPs can flood the inbox with fake contact form notifications, obscuring real leads.
- **Effort**: M
- **Suggested fix**:
  - Add origin validation in the worker: check `request.headers.get('Origin')` or `Referer` and reject calls not from `panoskokmotos.com`.
  - Alternatively, expose the secret only after a lightweight challenge (fetch a short-lived token from a `/token` endpoint that checks the origin). The current comment acknowledges this is intentional, but origin-pinning costs nothing and raises the bar significantly.

### 6. Two conflicting active-nav-link implementations run simultaneously

- **What**: `script.js:107-117` watches sections with `.nav-links a` and applies `a.style.color = '#fff'` inline; `script.js:783-796` watches `section[id]` and `div[id]` with `.nav-link` and toggles the `active` CSS class. Both observers fire on every scroll event.
- **Where**: `script.js:107-117` and `script.js:783-796`
- **Why it matters**: The inline `style.color` from the first observer overrides the class-based styling from the second, causing unpredictable highlight states (wrong link highlighted, stale highlights, flicker). Hard to debug because the cause is non-obvious.
- **Effort**: S
- **Suggested fix**:
  - Delete the first implementation (lines 107–117). It predates the class-based one and is strictly weaker (no active-class reset, inline style that overrides themes).
  - The second implementation at line 783 is complete and handles both sections and divs.

### 7. `.btn-givelink` uses off-brand colors (#6c4bff / #ff6268)

- **What**: The Givelink CTA button uses `#6c4bff` (purple) and `#ff6268` (coral-pink) in a gradient. The canonical Givelink brand palette is `#6B3FA0`/`#5718CA` (purple) and `#C2185B`/`#E353B6` (pink). The site colors diverge enough that the button doesn't match the actual Givelink app UI.
- **Where**: `style.css:202-203`
- **Why it matters**: Visitors who click through to givelink.app see different brand colors, which subtly erodes trust and looks like a different product.
- **Effort**: S
- **Suggested fix**:
  - Update the gradient to `linear-gradient(135deg, #5718CA, #E353B6)` to match Givelink's actual brand.
  - Add `--givelink-purple: #5718CA` and `--givelink-pink: #E353B6` as CSS custom properties to make future updates one-line changes.

## 🛠 P2 — Code health (tech debt slowing velocity)

### 8. `style.css` is 8,173 lines / 195 KB with no purge step

- **What**: The main stylesheet has grown to 195 KB. The build pipeline (`build.py`) only syncs partials — it has no CSS purge or tree-shake step. Many selectors (e.g., for pages that redirect to `tools.panoskokmotos.com`) are likely dead.
- **Where**: `style.css` (entire file), `build.py`
- **Why it matters**: 195 KB of CSS blocks first paint on every page. Even with caching, first-time visitors on 3G face a significant delay before any styled content appears.
- **Effort**: M
- **Suggested fix**:
  - Run PurgeCSS against all `.html` files and `.js` files to identify used selectors.
  - Add a `make build` or `npm run build` step that runs purge + minify and outputs `style.min.css`.
  - Target: under 60 KB for the minified stylesheet.

### 9. Service worker cache key `panos-v5` is hardcoded — stale-asset risk

- **What**: `sw.js:1` hardcodes `const CACHE_NAME = 'panos-v5'`. When CSS or JS assets are updated, the service worker must be redeployed with a new version string, otherwise returning visitors will load stale scripts from SW cache despite the `?v=` query-string cache-busters on the HTML `<script>` and `<link>` tags.
- **Where**: `sw.js:1`, HTML loads `style.min.css?v=20260912`
- **Why it matters**: A visitor who has previously loaded the site will keep running the old JS/CSS until they manually clear cache or the SW cache name changes. This can produce broken or partially updated UIs for returning visitors after a deployment.
- **Effort**: S
- **Suggested fix**:
  - Set `CACHE_NAME` to match the version string already used in HTML: `const CACHE_NAME = 'panos-20260912';`.
  - Better: generate the version string in `build.py` from the current date and inject it into both the HTML query params and `sw.js` during the build step.

### 10. `chatOpenWithBook` puts unescaped `title` and `author` into innerHTML

- **What**: `chat.js:228-234` builds `starters.innerHTML` by string-concatenating `title` and `author` directly with no HTML escaping. These values come from `onclick` attributes in `books.html`.
- **Where**: `chat.js:228-234`
- **Why it matters**: While the values are site-controlled today, any future book entry whose title contains `<`, `>`, or `&` would corrupt the DOM or cause display artifacts. It also sets a bad pattern that's easy to copy-paste incorrectly into a user-facing context.
- **Effort**: S
- **Suggested fix**:
  - Create a small `escapeHtml(str)` helper: `str.replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;')`.
  - Wrap `title` and `author` with it before injecting: `'Ask about <em>' + escapeHtml(title) + '</em>'`.

### 11. `followUpChips.sort()` permanently mutates the module-level array

- **What**: `chat.js:92` calls `followUpChips.sort(() => 0.5 - Math.random())` which sorts the array in-place. After the first call, the original order is lost forever; subsequent calls shuffle an already-shuffled array, which is fine for randomisation but is an unintentional side effect.
- **Where**: `chat.js:92`
- **Why it matters**: Low impact now, but if chips are ever added in a specific priority order (e.g., most-clicked first), this mutation will silently defeat that ordering.
- **Effort**: S
- **Suggested fix**:
  - Spread to a copy before sorting: `const shuffled = [...followUpChips].sort(() => 0.5 - Math.random()).slice(0, 2);`

### 12. Cookie consent banner hidden behind JS — invisible to non-JS users

- **What**: `index.html:518` (and all other pages) render the cookie banner with `style="display:none"` and rely on an inline `<script>` to show it if consent hasn't been given. With JS disabled or blocked, the banner never appears and analytics cookies (if loaded by other means) fire without consent UI.
- **Where**: `index.html:518`, same pattern in `now.html`, `goal.html`, and other pages (via the `gtag` partial)
- **Why it matters**: GDPR requires the banner to appear before any analytics scripts run. With JS blocked (e.g., in some corporate environments), users have no way to consent or decline.
- **Effort**: S
- **Suggested fix**:
  - Render the banner visible by default (`display: flex`) and use a `<noscript>`-friendly approach.
  - The inline script can then immediately hide it if consent is already stored: `if (localStorage.getItem('cookie_consent')) document.getElementById('cookieBanner').style.display='none';`.

## 💡 P3 — Nice to have

### 13. Confetti animation hardcodes colors that don't follow brand tokens

- **What**: `script.js:177` defines `COLORS = ['#3b6ef8', '#d4af37', '#10b981', '#f43f5e', '#8b5cf6', '#f97316']` as a local array, outside the CSS variable system. If the primary blue changes, the confetti won't update.
- **Where**: `script.js:177`
- **Effort**: S
- **Suggested fix**:

- **What**: The visible body says "Last updated March 2026" but the JSON-LD schema sets `dateModified: 2026-07-04`. One of these is wrong, and both are now stale (October 2026).
- **Where**: `now.html:81`, `now.html:221`
- **Effort**: S
- **Suggested fix**:

### 15. `search.js` renders result URLs as raw HTML without encoding — latent injection path

- **What**: `search.js:75-84` builds result links via template literals: `` `<a href="${r.url}" ...>` ``. If `search-index.json` ever has a URL containing `"` (e.g., a URL with a query string built by an automated tool), it would break the href attribute.
- **Where**: `search.js:75-84`
- **Effort**: S
- **Suggested fix**:
  - Wrap all dynamic values injected into innerHTML with an `escapeHtml` helper (the same one from item 10), or build result elements via `document.createElement('a')` and set `.href` directly instead of building HTML strings.
