## 🔥 P0 — Ship this week (bugs breaking user flows)

### 1. Wrong ARIA landmark role on every `<nav>`
- **What**: Every page uses `<nav id="navbar" role="banner">` — `banner` is reserved for the page-level `<header>`, not `<nav>`.
- **Where**: `index.html:580`, `goal.html:155`, `now.html`, `books.html`, `watch.html`, `beliefs.html` (all pages using the shared nav partial)
- **Why it matters**: Screen readers (NVDA, VoiceOver) announce the navigation as the "banner" landmark. The actual page header area has no `banner` landmark at all. Visitors using assistive technology get a confusing, broken navigation experience.
- **Effort**: S
- **Suggested fix**:
  - Wrap the `<nav>` in `<header role="banner">` on every page, e.g. `<header role="banner"><nav id="navbar" role="navigation">…</nav></header>`
  - Or simply remove `role="banner"` from `<nav>` (it already has an implicit `navigation` role); add a `<header>` wrapper with `role="banner"` around the entire nav block
  - Apply to all pages including the partial source (`partials/nav.html`)

### 2. Duplicate `FAQPage` JSON-LD schemas on homepage
- **What**: `index.html` contains two separate `<script type="application/ld+json">` blocks with `"@type": "FAQPage"` — one at line 201 (detailed, with `author` property) and another at line 459 (simpler version with partially overlapping questions).
- **Where**: `index.html:201–352` and `index.html:459–513`
- **Why it matters**: Google's documentation explicitly warns against duplicate structured data types on the same page. The search engine may ignore both schemas, costing rich-result eligibility (FAQ snippets in SERPs) which directly impacts click-through rate.
- **Effort**: S
- **Suggested fix**:
  - Keep only the first, more detailed schema (lines 201–352) which includes `author` attribution
  - Merge any unique questions from the second block into the first
  - Delete the second `FAQPage` block entirely

---

### 3. Contact form errors surface as browser `alert()` dialogs
- **What**: When a Formspree submission returns a non-2xx status or a network error, the code calls `alert('Something went wrong…')` and `alert('Network error…')`.
- **Where**: `script.js:409`, `script.js:415`
- **Why it matters**: Browser `alert()` is a modal that blocks the entire tab, looks like a browser security warning, and cannot be styled. On mobile it obscures the entire screen. Visitors who encounter a form error are left with a jarring experience and no in-context recovery path.
- **Effort**: S
- **Suggested fix**:
  - Add an `.form-error` element below the submit button (mirror the existing `#formSuccess` div pattern)
  - On error, populate and show it inline: `errorEl.textContent = 'Something went wrong. Please try again.'; errorEl.classList.add('visible');`
  - Style with `color: var(--red, #ef4444)` to match the existing design system

## ⚡ P1 — High ROI (UX friction blocking conversion)

### 4. Nav items differ between homepage and all inner pages
- **What**: `index.html` nav has `About · Milestones · Watch · Books · Now · AI Tools · Let's Talk`. All inner pages (goal.html, now.html, watch.html, books.html, etc.) have `About · Milestones · Watch · Books · Now · Beliefs · Let's Talk` — "AI Tools" is absent, "Beliefs" is absent from homepage.
- **Where**: `index.html:591–599` vs `goal.html:166–174` (and all other pages)
- **Why it matters**: Visitors who land on the homepage can't navigate to `/beliefs.html` via the nav. Visitors who arrive on any inner page see no link to the AI tools. Both are high-value pages. Inconsistent nav creates cognitive dissonance and dead ends.
- **Effort**: M
- **Suggested fix**:
  - Decide on a canonical 6-item nav; recommend: `About · Milestones · Watch · Books · Now · Beliefs · Let's Talk` (move AI Tools to its own promo card or hero CTA)
  - Update all pages to use this set, or implement a build-time partial injection (see item 9)

### 5. Chat proactively opens after 15 seconds on desktop
- **What**: On desktop, the AI chat panel auto-opens 15 seconds after page load (`script.js:467–492`) if the user hasn't interacted with it yet. It also replaces the initial greeting text.
- **Where**: `script.js:467–492`
- **Why it matters**: Auto-opening an overlay chat mid-reading interrupts the user's natural reading flow and can trigger an immediate close/back navigation, inflating bounce rate. The 5-second nudge tooltip (`chatNudge`) already handles passive discovery without being intrusive.
- **Effort**: S
- **Suggested fix**:
  - Remove the 15-second auto-open block entirely; the tooltip nudge + keyboard shortcut `/` are sufficient
  - Alternatively, increase the timer to 45–60s and only fire for users who have scrolled past the fold (indicating genuine interest)

### 6. `notifySecret` is hardcoded in client-side JS
- **What**: `shared.js:21` exposes `notifySecret: 'panos-notify-2026-xyz'` in plain text. Any visitor can view page source and call the `/notify` endpoint to send notification emails to the site owner at a rate of 20 per IP per hour.
- **Where**: `shared.js:21`, `cloudflare-worker.js:186–228`
- **Why it matters**: A motivated actor with multiple IPs (proxies, VPNs) can flood the inbox with spam notification emails. The rate limit is per-IP on the worker, which is trivially bypassed.
- **Effort**: M
- **Suggested fix**:
  - Remove the client-side notification of contact-form submissions — Formspree already sends the owner an email on every submission (this is its core value prop)
  - Keep `window.notifySite` as a no-op or remove it; the `/notify` endpoint can remain for server-to-server use only
  - If client notifications are needed, gate the `/notify` route with a Cloudflare Worker KV token generated per-session

---

### 7. Worker CORS wildcard exposes email delivery and AI API to all origins
- **What**: `cloudflare-worker.js:127` sets `Access-Control-Allow-Origin: '*'` on all routes including `/email-result` (sends mail from `tools@panoskokmotos.com`) and `/api/v1/tool` (burns Anthropic API credits).
- **Where**: `cloudflare-worker.js:126–129`
- **Why it matters**: Any third-party website can call these endpoints, use the AI tools for free (burning API budget at ~20 calls/IP/hr), and trigger outbound emails from your domain. The per-IP rate limit only protects at the worker level, not per authenticated origin.
- **Effort**: M
- **Suggested fix**:
  - Replace `'*'` with an origin allowlist: `['https://panoskokmotos.com', 'https://tools.panoskokmotos.com']`
  - Check the `Origin` request header in the worker and return `403` for unlisted origins on `/email-result` and the `/tool` family

### 8. Proactive chat mutates an existing bot message instead of pushing a new one
- **What**: The 15s auto-open script (`script.js:480–487`) directly changes the `textContent` of the very first bot message in the chat DOM. If a user has a stored conversation history re-rendered from `localStorage`, this mutation targets whatever the first `.chat-msg.bot` is — potentially overwriting a meaningful exchange.
- **Where**: `script.js:480–487`
- **Why it matters**: Users who return to the site with an existing chat history will see their first archived response silently replaced. Confusing, and undermines trust in the AI assistant.
- **Effort**: S
- **Suggested fix**:
  - After `toggle.click()`, use `addMessage('bot', '…')` to push the proactive message at the end of the chat, rather than mutating `existing[0]`
  - This also allows the nudge message to co-exist with loaded history naturally

## 🛠 P2 — Code health (tech debt slowing velocity)

### 9. Nav HTML is copy-pasted verbatim across 6+ pages
- **What**: The `<!-- include:nav -->` / `<!-- /include:nav -->` comment fences in every page are documentation, not execution — `build.py` or equivalent doesn't enforce them. The nav HTML block (~50 lines) exists as a literal duplicate in every page file.
- **Where**: `index.html:580–640`, `goal.html:154–205`, `now.html`, `books.html`, `watch.html`, `beliefs.html`
- **Why it matters**: Changing any nav item (as demonstrated by the homepage/inner-page divergence in item 4) requires editing every file. Missing a file creates the inconsistency already seen.
- **Effort**: L
- **Suggested fix**:
  - Add a `build.py` step (or extend the existing one) that reads `partials/nav.html` and performs string substitution between `<!-- include:nav -->` and `<!-- /include:nav -->` on every page before minification
  - Until then, a simpler fix: add a "last synced" comment with a hash at the top of each nav block so drift is immediately visible in diffs

### 10. GDPR cookie-consent HTML and inline script duplicated on every page
- **What**: The full cookie banner HTML (~25 lines) and the inline consent-checking `<script>` block are copy-pasted identically into every page's `<body>`.
- **Where**: `index.html:518–560`, `goal.html:92–134`, `now.html`, and all other pages
- **Why it matters**: Any change to the consent flow (e.g. adding a "Manage preferences" option, updating privacy policy links) must be replicated across every file. The risk of missing a page is high.
- **Effort**: M
- **Suggested fix**:
  - Extract the banner HTML into `partials/cookie-banner.html` and inject it via the same build-step approach as item 9
  - Or load the banner dynamically from `shared.js` on DOMContentLoaded (a `document.body.insertAdjacentHTML('afterbegin', bannerHtml)` approach)

### 11. `goal.html` ships a v1 chat widget; `index.html` uses v2
- **What**: `goal.html:336–393` contains an older, minimal chat widget structure missing: the status dot (`.chat-status-dot`), the mic button (`#chatMic`), the size-toggle button (`#chatSizeToggle`), and the nudge element (`#chatNudge`). `chat.min.js` is loaded on both pages but silently no-ops on the missing elements.
- **Where**: `goal.html:336–393` vs `index.html:2162–2231`
- **Why it matters**: Visitors to `/goal.html` — the primary conversion page — experience a degraded chat widget compared to the homepage. Voice input and the size toggle are unavailable there despite the JS loading them.
- **Effort**: S
- **Suggested fix**:
  - Copy the v2 chat widget markup from `index.html:2162–2231` into `goal.html`, replacing the v1 block

### 12. Service worker cache version is a hardcoded string
- **What**: `sw.js:1` defines `const CACHE_NAME = 'panos-v5'`. When assets change, the cache key must be manually bumped — otherwise returning visitors keep stale assets until the browser expires the old cache.
- **Where**: `sw.js:1`
- **Why it matters**: The CSS and JS files use query-string versioning (`?v=20260912`), but the SW caches the raw URL without the query string for some assets. A mismatch means a user can have a fresh service worker but still serve a stale `style.min.css`.
- **Effort**: S
- **Suggested fix**:
  - Change `CACHE_NAME` to incorporate a build date: `'panos-' + new Date().toISOString().slice(0, 10).replace(/-/g, '')` generated at deploy time
  - Or add a `build.py` step that writes the current date into `sw.js` before pushing

### 13. `index.html` has no `<header>` element wrapping the nav region
- **What**: Beyond the ARIA `role="banner"` bug (item 1), the page structure goes `<body> → <div#cookieBanner> → <div#page-loader> → <a.skip> → <div#progress-bar> → <nav>`. There is no `<header>` element on any page.
- **Where**: `index.html:515–580`, all other pages
- **Why it matters**: Structural HTML5 landmark elements (`<header>`, `<main>`, `<footer>`) are used by accessibility tools and browser reader modes. `<main role="main">` is present, `<footer>` is present, but `<header>` is entirely absent.
- **Effort**: S
- **Suggested fix**:
  - Wrap the `<nav>` in `<header>` on every page; move `role="banner"` to the `<header>` (this also resolves item 1)

## 💡 P3 — Nice to have

### 14. Dark mode is JS-forced; light mode CSS exists but is unreachable
- **What**: `script.js:120` runs `document.documentElement.setAttribute('data-theme', 'dark')` unconditionally. `style.css:881–906` defines a complete `html[data-theme="light"]` ruleset that is never applied.
- **Where**: `script.js:120`, `style.css:881`
- **Why it matters**: Users with OS-level light mode preference never see the designed light variant. The CSS work has already been done — there's no way to trigger it.
- **Effort**: M
- **Suggested fix**:
  - On load, read `localStorage.getItem('theme')` first; fall back to `window.matchMedia('(prefers-color-scheme: light)').matches` to set the initial theme, then add a theme toggle button to the nav
